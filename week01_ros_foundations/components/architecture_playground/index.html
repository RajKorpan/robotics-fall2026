Part 2: Robot software architectures

How should a robot organize its decisions?

A robot architecture is the structure used to divide sensing, decision making, action, and safety among software components. You will run the same hospital delivery task using four architectures and watch how each one handles a changing hallway.

The difference is how the robot makes the decision. A reactive system responds immediately. A deliberative system uses stored information to plan ahead. A behavior-based system coordinates several small responses. A hybrid system combines planning with fast local responses.

Example 1

Reactive architecture: respond to what is sensed now

A reactive robot uses a direct rule such as “if something is close, stop.” It does not need a stored map or a plan. This makes the response fast, but the rule does not tell the robot how to finish its delivery after it stops.

Stimulus-response rule: a specific sensor condition immediately produces a specific action.

What to do

  1. Run the clear hallway and follow the Sense, Decide, Act sequence.
  2. Run the hallway with a cart. Each run begins at the starting position.
  3. Notice that the robot responds safely but has no plan around the cart.

Example 2

Behavior-based architecture: coordinate several small purposes

A behavior is a small process with one purpose, such as following a goal or avoiding an obstacle. Several behaviors can request different motor commands at the same time.

Arbitrator: the component that decides which requested action controls the robot when behaviors disagree.

What to do

  1. Run with no conflict and watch Follow goal win.
  2. Run with a cart and read each behavior’s requested action.
  3. Watch the arbitrator give Avoid obstacle temporary control.

Example 3

Deliberative architecture: use a model to plan ahead

A deliberative robot stores a representation of the hallway, robot, destination, and obstacles. A planner searches that world model for a sequence of movements that should reach the goal.

World model: stored information about the robot and environment. Planner: software that uses the model to select a sequence of actions.

What to do

  1. Run with an accurate map and watch the planned route.
  2. Run with an outdated map. A cart appears on the saved route.
  3. Watch the robot pause while its model and route are updated.

Example 4

Hybrid architecture: plan ahead and react locally

A hybrid robot separates slower route planning from fast local responses. An executive coordinates the layers. If a cart suddenly blocks the route, the local layer can stop immediately while the planner works on a new route.

Executive: the layer that coordinates planned goals with current robot status. Local response: a fast decision based on nearby sensor information.

What to do

  1. Run normal delivery and watch commands pass through all layers.
  2. Run with a sudden cart.
  3. Watch the local layer stop first, report the blockage, receive a new route, and resume.

Example 5

Layered safety: restrict an unsafe command

A planner, behavior, or person can request a speed that is inappropriate near people. A separate safety layer checks the command before it reaches the motors.

Safety override: a rule with authority to replace or block another component’s command when executing it would violate a safety limit.

What to do

  1. Run without the safeguard and watch the 0.8 m/s command enter the danger zone.
  2. Run with the safeguard using the same requested speed.
  3. Compare the command received by the motors and the final stopping position.
